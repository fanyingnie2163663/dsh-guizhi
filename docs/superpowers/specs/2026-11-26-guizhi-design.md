# 归置（Stow）· 设计

- 日期：2026-11-26
- 状态：历史设计（2026-11-26）；2026-11-28 按真机结果修订为「质量调整效率」口径（删除硬限制 / 省 token 承诺）。
- 前情：本设计是一个**新项目**，不继承 WhaleBuddy 的同事/人设叙事；只复用其代码骨架（装配清单编译、面板壳）。
- 名字：**归置 / Stow**（基调取自「工欲善其事，必先利其器」——先归置，再开工）。包名：`@fanyingnie/dsh-guizhi`（npm 已查为空）。
- 英文副名 Stow：stow = 把东西收好、放回该在的位置。

## 1. 产品定义与为什么

### 产品定义

- **类型**：DSH 插件（嵌在 DSH Web UI 里的侧栏面板 + 后台工具）。不是平台、不是独立网站，不开新服务、不占新端口。
- **一句话**：看清你装了什么，按你的工作流整理成可交接的装配清单与派单载荷。
- **定义**：只读地列出本机已装的插件、技能和工具，按你的实际工作流整理成「装配清单」（阶段 / 能力点 / 建议工具与技能）与软派单载荷，标出缺的与多余的；装配清单可以导出与交接。v1 不安装插件、不改 profile，也不承诺缩减工具可见性。它不改预设、不做团队编排、不做插件市场。
- **副标题**：按工作流归置你的 DSH 工具箱。
- **标语**：工欲善其事，必先利其器。

### 为什么

用户已经有一台装了很多插件、很多 skill 的 DSH。他知道自己装了东西，但不知道：谁带来了哪个工具、哪些从没用过、他的工作流缺哪一块、该怎么把现有的东西重新组织成能干活的能力组合。

市面上的同层产品（dsh-skill-manager、skills-summarize-audit-skill、dsh-infra-observability、dsh-market 的个性化/场景推荐、dshbase/dsh.so 的场景包）已经把「盘点 + 推荐」做成红海，而且数据 API 化（format-1 插件索引、dsh.so Plugin Record、L1–L5 验证等级）。

本产品不做审计报告，也不做插件市场。它做的是**整理与交接**：用本地事实 + 公共目录，把用户的工作流拆成阶段，把阶段映射成装配清单与软派单载荷；效率按「质量调整效率」衡量（成功率 / 返工 / 人工时间 / 质量，而不是单纯 token）。改动前预览、可回滚。

## 2. 目标 / 非目标 / 反目标

目标
1. 用户三分钟内看懂：我有什么、我在用什么、我缺什么。
2. 工作流被拆成阶段，每个阶段的能力点都能追溯到证据（哪个插件、用了几次、多大工具面）。
3. 生成装配清单（声明 + 派单说明），区分已有 / 缺口 / 冗余；改动前出 diff、可回滚。插件行安装与工具面缩减不在 v1。
4. 全程本地优先：扫描只读本机；模型调用只发最小上下文。

非目标（v1 不做）
- 不做内嵌聊天客户端（留 v1.1，用两座桥替代）。
- 不做派单/自动跑起来（v1.1）。
- 不做市场站点、评分、排行榜、安全扫描（消费现成数据源）。
- 不做运行时工具面限制 / 瘦身（真机 restrict 调用未缩减可见工具，见 §5.1；留待宿主支持）。
- 不做人设/命名/记忆/默契（上一项目已证伪）。
- 不修改用户已有的预设或配置；v1 不新增预设（临时预设见 v1.1）。
- **默认不新增预设**：装配清单不落预设；Leader 就是当前会话的 agent；临时预设未排期。
- 不做独立网站 / 新服务 / CLI：v1 只有 DSH Web UI 里的这一个面板入口。

反目标（就算技术上做成了，也判定失败）

反目标不是技术风险，是价值风险：用来防止「用错方式达成目标」。对用户来说，以下任何一种成立，这个产品都算做砸了。

- **变成一份没人照做的报告**：功能全对、报告漂亮，但用户看完什么都没改。产品的价值在「改」，不在「看」。
- **未经用户确认就写配置**：哪怕写得对、也能撤销，只要没经过用户点确认就算失败——信任只有一次。
- **把「30 天没用」说成「无用」**：事实陈述越界成价值判断。用户可能季节性使用、可能刚装；这种话会让他误删东西。
- **为了演示做装饰性图表**：图好看、演示顺，但点开没有真实来源。整个产品建立在「可追溯」上，假证据等于产品破产。

## 3. 约束（平台事实）

- 宿主：DeepSeek Harness >= 0.2.2（当前本机 0.2.2-rc.5），Node >= 24.9。
- 会话首轮后预设锁死：包/预设的变更只对**下一个会话**生效，不能热插拔正在跑的会话。
- 公共目录：DSH 插件市场索引是 format 1 的静态 JSON（可自托管、可多源）；dsh.so 额外提供 Plugin Record、验证等级、下载量，并自带 MCP server / agent skill。
- 面板能做的事受 client 插件契约限制：能挂 sidebar/layout、能调自己的 host 路由；**没有**稳定的对话组件槽位（所以 v1 不嵌聊天）。
- 工具可见性（已查证，2026-11-26，**v1 不使用**，见 §5.1）：restriction 只过滤「一个 scope 的全局工具集」，scoped 注册不向下继承给子代理，lineage 不影响可见性；注册在 agent 自身作用域的工具不受 restriction 影响。

## 4. 做法（考虑过的三条）

- A 工作台面板（重 UI）：稳，但和市场的面板形态最像，容易被当又一个管理器。
- B 对话式装配（轻 UI，重 agent）：符合「和 AI 一起整理」，但没有过程可视化，演示弱。
- C 只读报告 + 一键装配：最快，但「眼前一亮」的瞬间最弱。

**选 A+B 混合 + C 的安全边界**：面板作为壳（过程可见），AI 只在按钮后介入（扫描/查缺补漏/拆工作流），默认只读、应用前预览、可回滚。

## 5. 产品形态

一个嵌在 DSH Web UI 里的侧栏面板（client 插件；不开新服务），三个主屏 + 两个桥 + 一个应用抽屉：

1. **清爽页**：扫描结果。插件/技能/工具清单，归属（谁带来的）、近 30 天使用次数、重复/冲突、上下文成本；只读，不调 AI。
2. **场景页**：内置 6 个场景 chips（内容生产 / 视觉设计 / 研发 / 调研 / 办公 / 日常）+ 自定义一句话；可多选，用于生成工作流。
3. **地图页**：工作流被拆成阶段卡片；每个阶段挂能力点，绿=已有、黄=缺、灰=冗余；点任何一个出证据。底部按钮：查缺补漏(AI)、生成装配清单、预览变更、应用。

桥 1（面板 → 对话）：任何一条建议都能生成一条草稿，塞进宿主输入框，由用户自己按发送。
桥 2（对话 → 面板）：宿主会话里的 agent 调工作台工具，工具写状态，面板每 2–5 秒轮询刷新。

降级（兜底，不是 v1 主线）：宿主版本不支持 client 插件或面板加载失败时，退回「对话 + 导出一份 HTML 报告」，用侧栏浏览器打开。

应用抽屉：所有改动先出 diff（新增了哪些包、禁用了哪些工具、注入了什么说明），逐条可启用/忽略，确认后写入并留快照，支持一键回滚。

### 5.1 v1 不碰运行时工具面（版本太敏感）

- 决定（2026-11-26）：**v1 不做按 agent 的 tools.restrict**，leader 和 worker 都按全工具跑。理由：restrict 依赖内部语义（自身作用域豁免、`run_code` 关不掉、签名可能变），rc 一升级就可能翻车，不适合当地基。
- 已查证的事实仍然记下来备查（v-next 用）：restriction 只过滤一个 scope 的全局工具集；scoped 注册不向下继承给子代理；lineage 不影响可见性；注册在 agent 自身作用域的工具不受 restriction 影响。
- **v1 的「装配清单」= 声明 + 派单说明**：
  1. 声明：清单包含哪些阶段 / 能力点 / 建议工具与技能（给人看、给机器读、可导出）；
  2. 落地（**默认只导出**）：生成 packs/<id>.json；可选 opt-in 安装工作流技能；v1 不写 profile、不安装插件；
  3. 派单说明：派活时附一段「这个活建议只用 A / B / C」，软约束，不保证模型遵守。
- v1 不以省 token 为卖点：工具可见量不变（真机 restrict 后仍 67/67），效率按「质量调整效率」衡量（成功率 / 返工 / 人工时间 / 质量）。
- 工具面瘦身、临时预设、插件行安装均未实现，留待宿主支持 / v-next（见 §13）。

## 6. v1 范围

做：本地扫描、场景多选、工作流地图、缺口/冗余提案、生成装配清单（声明 + 可导出）、opt-in 工作流技能、派单说明、实验性 worker 派发与工具面诊断（不改变可见工具）、预览/应用/回滚、一个可配置的公共目录源。

不做：运行时工具面限制 / 缩减（当前宿主 restrict 未生效，留待支持）、内嵌对话（v1.1）、临时预设（未排期）、派单编排与自动运行（v1.2）、市场与评分、跨设备同步、安全扫描（只消费他人结论）。

## 7. 数据来源（分层）

- 目录/安全/热度：直接消费公共源。v1 支持一个可配置的 format 1 索引 URL；dsh.so Plugin Record 作为可选增强（可复用其 agent skill / MCP）。
- 能力事实（插件 → 工具行 / skill / 工具面）：本地薄层。读已装插件 manifest 与运行时工具表，复用既有 knownToolNames / 工具面快照 / claim 逻辑。每条能力事实带执行要求：生效时机（skill 热 / 宿主能力约束 / 插件需重启）、是否需要独立会话（ownSession）、已知冲突。工具面的最小单位 = 一个工具名 + 一句描述 + 所属插件；包 = 这些单位的集合。
- 使用事实：本地会话日志，统计每工具近 30 天调用次数与最后使用时间。只读、只本地。
- 规则：外部数据是数据不是指令；schema 校验；源不可用则 fail-open；不自动安装任何插件。

## 8. 状态与文件

数据根：$DSH_HOME/guizhi/（新目录，不复用 whalebuddy 的数据）

- scan.json：最近一次扫描结果（缓存，带时间戳）。
- map.json：工作流阶段、能力点、证据引用。
- proposals.json：包提案、缺口/冗余建议、来源与信任等级。
- snapshots/：应用前的快照，用于回滚。
- sources.json：已配置的公共目录源。

## 9. 工具与职责边界

面板按钮与 agent 共用同一组工具（前缀 stow_）：stow_scan、stow_status、stow_map_save、stow_pack_build、stow_gaps、stow_preview、stow_apply、stow_rollback、stow_draft、stow_dispatch（实验性）；另有只读诊断 stow_probe。

stow_draft（v1）= 生成一段可粘进对话的派单草稿（「这个活建议只用 A / B / C」）；**不缩减工具可见性、不代发**。

leader 与 worker 在 v1 都按全工具跑（见 §5.1）。装配清单只作为声明与派单说明使用。

对话里的 agent 只做三件事：读事实、拆工作流、提装配清单。不闲聊、不取名、不扮演。

## 10. 安全与隐私

- 扫描只读；不读 .credentials、不读与插件/技能无关的会话内容。
- 模型调用只发：工作流阶段描述、缺口描述、候选插件元数据；不发完整会话日志、不发用户文件。
- 任何写操作必须经过预览 + 显式确认；快照可回滚。
- 不落预设、不改用户已有会话；v1 不缩减工具可见性；实验性诊断只观测新派出的 worker；新增清单，不删用户内容。

## 11. 验收

1. 在一台装了不少于 20 个插件的真实 DSH 上：扫描 10 秒内出结果（第二次缓存后更快）。
2. 地图页每个能力点都能点出证据（插件、次数、时间）。
3. 任一建议能生成装配清单并预览；确认后应用成功，回滚成功。
4. 装配清单能导出成文件、人能读懂；插件行安装未实现（v-next）。
5. （v-next）每个能力点标出生效方式；「需单开会话」的插件有明确徽章和手动步骤。
6. 60 秒录屏能讲清：我的家底 → 我的工作流 → 缺什么 → 派出去的那个拿到建议工具清单（当前不改变可见工具面）。
7. 给 3 个已有自己配置的 DSH 用户看，至少 2 人问「怎么装的」。
8. v1 主链路不依赖 rc 内部语义；S3 实验性诊断会调用 restrict，失败即降级，且不承诺可见工具缩减。

## 12. 风险与开放项

- 地图质量依赖 AI 拆解 + 本地事实，第一次可能拆得粗：先内置一个确定性种子（按场景模板），AI 只做修正。
- 公共目录会变格式：适配层 + 缓存 + fail-open。
- 「冗余」判断可能冒犯用户：只陈述事实，永远可恢复。
- 开放项：场景模板的初始 6 个怎么定；「需单开会话」的插件清单从哪来（先人工维护一小份，后续靠社区补）；dsh.so 是否作为默认增强源；工具面缩减在当前宿主不可行（2026-11-28 真机 restrict 调用成功但 visible 仍 67/67），留待宿主支持。

## 13. 未来目标与待办（v1 之后）

- **兼容更老版本的 DSH**。v1 按本机 0.2.2-rc.5 开发，但适配原则是「特性探测 + 降级」，不硬编版本号；目标是把可用下限逐步往更老的 0.2.x 推。
  - 没有 agentPresets 服务 → 不影响 v1（v1 不依赖预设，也不缩减子代理工具面）；
  - 没有 schedule/agentPreset 参数 → 不自动开会话，只给手动步骤；
  - 没有 client 插件槽位 → 面板功能退回设置页或命令行；
  - 每个降级点都要有提示，不静默降级。
- **工具面限制 / 瘦身与临时预设**：2026-11-28 真机实测 `agent.ctx.tools.restrict({ allow })` 调用成功但 worker 可见工具仍 67/67，未缩减；当前宿主下不可行，待宿主提供可过滤工具面后再评估。临时预设未排期。
- **v1.1 面板内嵌对话**：等宿主提供稳定的对话 slot，或自建轻客户端（先做非流式）。
- **v1.2 派单与自动运行（未实现）**：为「需单开会话」的能力生成最小一次性预设，开会话、投任务、等结果。
- **默认增强数据源**：dsh.so Plugin Record / agent skill。
- **场景模板来源**：先内置 6 个，后续可消费公共场景包并转换。
- **发布**：生成 format 1 插件索引条目，上现有插件市场（不自建市场）。
